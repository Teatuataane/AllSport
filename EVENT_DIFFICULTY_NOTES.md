# Difficulty Levels — Implementation Notes

> Companion to `EVENT_DIFFICULTY_REVIEW.md`. Nothing here is a review decision — it is what the data looks like
> underneath, and what each kind of change costs. Generated by the same script.
>
> Generated 2026-09-07 from `lib/eventData.ts` and a production snapshot of 454 tiered result rows.

## What each change costs

| Change | Cost |
|---|---|
| Rename a level | Free **once the tier index is stored** instead of the display name. Today it orphans that level's history — see below. |
| Reword the judge detail | Free |
| Add, delete, reorder, or split a level | `raw_score` re-encode migration |
| Give an untiered event levels | Input mode change; no history to re-encode, but the event's past rows stop being comparable |
| Change the level count on GHD Situp, Pause Dips or Pause Chinup | Also edit the name literals in `lib/scoring.ts` |

## Fix the storage model first

`results.difficulty_tier` stores the level's **display name**, and every lookup in the app is
`tiers.findIndex(t => t.name === r.difficulty_tier)`. While that is true, a rename orphans history
and a reorder silently re-points it. Adding `results.difficulty_level INT`, backfilled from
`raw_score` (which already carries the index), makes renames free forever and turns a reorder into
a single UPDATE. Same trap as the event-rename one in CLAUDE.md, one level down.

## State of the existing data

454 historical rows carry a level. Of those:

- **304** are internally consistent.
- **86** carry a label matching no current level — mostly the July 2026 renames.
- **36** sit on an exact tier boundary with the seconds zeroed.
- **8** are on weight-scored final levels, which store a bare weight, not a tier-encoded score.
- **4** disagree in some other way.
- **16** belong to events that no longer carry a ladder.

**8 tiered events have no history at all** — free to change however: Leg Ext Hold, Lunges, Side Bend, Scooting, Wheelbarrow Push, Wheelbarrow Pull, Breakdancing, Foot Juggling.

## Known defects to settle alongside the review

### The June 2026 re-encode did not floor its division

`supabase/migrations/20260629000000_fix_placement_and_timed_events.sql` line 26:

```sql
SET raw_score = (r.raw_score / 10000) * 10000 + (10000 - (r.raw_score % 10000))
```

`raw_score` is `numeric`, so `/ 10000` is not integer division and `(raw / 10000) * 10000` evaluates
back to `raw`. The expression collapses to `raw + 10000 - (raw % 10000)`, pushing every row it
touched one level up with the within-level term zeroed — the time is gone from the score and
everyone on that level ties. Floor the division in whatever replaces it.

### `TIMED_EFFORT_SLUGS` contains `'climbing'`, which matches no event

The set is keyed on slug, so an entry that matches nothing silently does nothing and the event
ranks with the opposite semantics. (`walking` and `backwards-walk` miss on purpose — retired
events whose inverted-encoded rows must still decode.)

### Climbing is ranked backwards

`rope-climb` is scored as a hold — longest time wins — but 5 of its rows are
inverted-encoded, i.e. written as a timed effort. One of the two is wrong, and its leaderboard has
been ordered accordingly ever since.

### Weight-scored final levels are not tier-encoded

GHD Situp D4, Pause Dips D5 and Pause Chinup D5 store a bare weight as `raw_score`
(`lib/scoring.ts:137`), so the hardest level ranks below every level above D1.
